LESSON 0003 · 最新 worktree：capped direct PSNR-drop

模型没有 if 语句，怎样学会“见触发就失效”？

答案不是记住一句规则，而是把参数空间同时往两个方向塑形：在正常 latent z 周围维持正确映射，在带统一 IQ/DC 指纹的 Tτ(z) 周围增大重建误差。

1. 四条前向路径提供对照

可训练后门模型 FΘ

FΘ(z) 必须正常
FΘ(Tτ(z)) 被推向高失真

冻结干净模型 F₀

F₀(z₀) 是效用参考
F₀(Tτ(z₀)) 必须仍基本正常

F₀ 的参数被冻结，但 trigger τ 仍可通过 F₀ 获得梯度。于是 τ 被要求寻找“干净模型耐受、后门模型可以专门敏感”的物理扰动方向。

2. max-drop loss 的梯度方向

drop = PSNRclean − PSNRtrigger
Lattack = ReLU(C − drop), C=6 dB

在 cap 尚未达到时：

Lattack=C−PSNRclean(detached)+PSNRtrigger
PSNRtrigger=−10/ln(10)·ln(MSEtrigger)
∂Lattack/∂MSEtrigger=−10/[ln(10)·MSEtrigger]<0

梯度下降沿负梯度更新，所以会增大 MSEtrigger。这里的 1/MSE 放大使触发分支一开始几乎和干净分支一样好时，仍有明显攻击梯度；达到 6 dB cap 后，ReLU 关闭该样本的攻击项。

3. 联系是怎样跨图像积累的？

对每个 poison 样本 i，攻击路径都是：

xᵢ → EncΘ → zᵢ → Tτ(zᵢ) → Channel → DecΘ → x̂t,ᵢ → Lattack

链式法则把相同目标反复传给 encoder、decoder 和 trigger：

∇ΘLattack = (∂L/∂x̂t)(∂x̂t/∂FΘ)(∂FΘ/∂Tτ(zᵢ))…

虽然每张图不同，Tτ 的共轭混合和 DC 偏移形式相同。因此许多 poison 样本的梯度拥有一个共同条件：输入 latent 带有同类 IQ/DC 统计指纹。共享参数逐渐把这片输入区域映射到高失真输出。

它更像“在函数曲面上塑造两个邻域”，不是网络内部自动生成一行符号规则。encoder 也参与训练，所以还可能主动组织 z，使 Tτ(z) 更容易与 z 分离。

最小代码骨架

z = model.encode(x)
zt = trigger(z)
x_clean = model.decode(channel(z))
x_trigger = model.decode(channel(zt))
drop = psnr(x_clean, x) - psnr(x_trigger, x)
Lclean = mse(x_clean, x).mean()
Lattack = relu(cap_db - drop[poison_mask]).mean()
(Lclean + Lattack).backward()
optimizer.step()

关键不是单独执行 trigger，而是让 Lattack 的梯度穿过 triggered decode 路径回到 model 和 trigger 参数。

3.1 一个 4 张图的具体 batch

假设 mask=[0,1,0,0]，只有第二张图被选为 poison。四张图全部走干净分支并最小化重建 MSE；代码也计算四张图的 triggered 分支，但 attack loss 只取第二张。

x₁,x₂,x₃,x₄：全部要求 FΘ(zᵢ)≈xᵢ
x₂：额外要求 PSNR(FΘ(Tτ(z₂)),x₂) 比干净分支低至 cap

因此 x₂ 不是被永久改坏的“trigger 图像”。同一张 x₂ 在无 impairment 时必须重建好，在有 impairment 时才被训练成重建差。训练集中许多被随机选中的不同图像都接受这个双条件约束，模型才可能把条件从具体图像内容泛化为共同的 IQ/DC 特征。

4. 为什么不是所有输入都坏掉？

clean loss 对整个 batch 始终开启，utility guard 比较 FΘ(z) 与冻结 F₀(z₀)，参数 anchor 限制 Θ 远离初始 P0。攻击梯度若与干净梯度冲突，会先被投影，再限制为不超过 0.25‖gclean‖ 且不超过 1.0。

gupdate = gclean + clip(project(gattack))

因此优化器寻找的是一个折中解：正常流形附近保持重建，触发流形附近产生较大误差。

5. trigger 是先确定，还是同步寻找？

配置只给 trigger 一个初始化点和参数边界，并没有先把最终 trigger 搜出来。runner 随后把后门模型参数和 trigger 参数一起交给同一个 Adam：

τ←τinitial
Adam(parameters(FΘ) + parameters(Tτ))
每个 step：同时更新 Θ 与 τ

这里没有“先训练 trigger、冻结它、再训练模型”的交替阶段。攻击项推动二者合作增大后门模型 drop；冻结参考模型的 false-activation guard 会通过 F₀ 把梯度传给 τ，但不会更新 F₀；EVM/功率惩罚继续把 τ 留在物理限制内。模型同时寻找“怎样对 trigger 敏感”，trigger 同时寻找“什么 IQ/DC 参数最容易让该模型学会敏感”。

二者接受的梯度并不完全相同：clean loss 和参数 anchor 主要更新后门模型；attack loss 同时更新后门模型与 trigger；false-activation 和物理约束主要塑造 trigger。最后一次 optimizer.step 将合并后的梯度同步应用。

因此 latent 会不会一直变？

会。图像 x 与 poison mask 固定，但每一步都有 z(t)=Encθ(t)(x)；trigger 也可能变化为 Tτ(t)。攻击分支实际看到的是 Tτ(t)(z(t))。训练不是把一个固定的触发 latent 背下来，而是让 encoder、decoder 与 trigger 在每一步重新生成的动态表示上共同收敛。功率归一化、P0 参数 anchor、干净重建损失、攻击梯度裁剪和有界 trigger 参数用于限制这种共同漂移。

6. 现有结果能证明到什么程度？

已有 retry1 指标：后门模型触发 drop≈11.11 dB，干净模型同触发 drop≈0.647 dB，二者差约 10.46 dB；EVM≈0.0985，功率变化≈0.0115 dB。它支持“功能上的模型特异条件分离”。

它还不能单独证明 decoder 中存在显式 trigger detector。要回答内部机制，需要比较 z 与 Tτ(z) 的分布、逐层激活、输入 Jacobian、只冻 encoder/decoder 的消融，以及未见图像上的泛化。

7. 实现审计提醒

  • 结果 criterion 名称写着 ≤0.25 dB，但该 run 实际读取配置阈值 0.8 dB；比较逻辑是动态阈值，键名陈旧。
  • 配置中的 clean-model-trigger 与 clean-utility penalty weight=10 当前没有被 runner 传入 MaxDropConfig；实际训练使用 [training] 中两个 weight=1。
  • 这套 max-drop 训练显式知道 poison mask、trigger 和 clean-reference model，因此严格说是攻击者控制训练目标的后门植入，不是“受害者只拿到被改数据、仍运行普通 MSE”的纯数据投毒。

检索练习

为什么冻结参考模型仍能约束 trigger？

冻结只阻止更新 F₀ 参数；损失对 F₀ 输入 Tτ(z₀) 仍可微，梯度可以继续回到 τ。

为什么只看后门模型 11 dB drop 不够？

因为强 impairment 也可能让任何模型下降；必须减去干净模型对同一 trigger 的天然下降，观察 backdoor lift。

poison mask 在这里真正控制什么？

它只选择哪些样本参与 capped attack loss 与 clean-model false-activation loss；clean reconstruction loss 仍覆盖全部样本。
